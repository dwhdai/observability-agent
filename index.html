🔍 Agent Capabilities

🗄️

DB Querying

Agent generates and executes SQL against live metrics and logs tables. Retrieves targeted, structured results rather than requiring raw data to be loaded into context.

⚙️

Sandboxed Code Execution

Agent generates Python analysis scripts — stats, percentiles, aggregations — that run in a sandboxed subprocess. Only the computed result returns to the model, offloading computation and keeping message history lean.

🎛️

Control Dashboard

Updates filters (service, metric, log level, time range) and freezes the UI for focused inspection during diagnosis.

🛡️

Scope Validation

Rejects out-of-scope queries with structured refusals. Dynamic system prompt built from live DB introspection prevents hallucination.

📝

Audit Logging

Every session produces a JSONL trace with full message history, tool calls, timestamps, and rejection reasons.

🔗

Multi-turn Context

Maintains full conversation history across turns. Supports follow-up questions, clarifications, and iterative investigation.

🔄 Request Lifecycle

1

User Input

Natural language query enters the chat loop. Usage limits enforced: max 25 tool calls per session to prevent runaway execution.

UsageLimits(request_limit=25) message_history preserved
2

Scope Check via Structured Output

Model returns AgentResponse(accepted: bool, rejection_reason, response). Out-of-scope queries are caught at the type level — not post-hoc.

output_type=AgentResponse Pydantic validation
3

Tool Dispatch

Agent selects tools based on intent. Can chain multiple calls in a single turn. Tools injected via RunContext[Deps] dependency pattern.

_run_analysis

Execute SQL + optional Python script. Row cap: 500. Timeout: 2s SQL / 5s script.

_update_dashboard

Merge partial DashboardUpdate into shared state. Type-safe, merge semantics only.

4

Tool Execution (Sandboxed)

Python post-processors run in a subprocess with blocklist validation. Blocked patterns: import os, open(, exec(, network calls. Allows math/stats only.

blocklist validation threading + interrupt no filesystem/network
5

Response + Trace

Structured response returned to user. Full session written to agent_traces/<timestamp>.jsonl. History appended for next turn.

JSONL audit log result.all_messages()

🧠 Dynamic System Prompt

The system prompt is rebuilt each session from live DB introspection — not hardcoded. This grounds the agent in the actual available data and prevents hallucination about non-existent services or metrics.

# agent.py — _build_system_prompt()

def _build_system_prompt(available_data: dict) -> str:
    services = available_data["services"]   # queried from DB at startup
    metrics  = available_data["metrics"]    # ["latency_p99", "error_rate", ...]

    return f"""
You are an SRE observability assistant. You ONLY answer questions about
the metrics and logs in the database.

Available services: {services}
Available metrics:  {metrics}
Data window:        last 30 minutes at 5s resolution

Health thresholds:
  - latency_p99 > 500ms  → degraded
  - error_rate  > 0.5%   → degraded
  - cpu_usage   > 80%    → degraded

STRICT: Reject any query not answerable from this data.
Set accepted=False and populate rejection_reason.
"""

📐 Design Patterns

Pattern Implementation Purpose
Multi-turn chat loop agent.run_sync(…, message_history) Preserves conversation context across turns for follow-up investigation
Dependency injection Deps(db_path) via RunContext[Deps] Tools receive runtime context (DB path) without global state
Structured output output_type=AgentResponse (Pydantic) Scope validation and rejection reason are enforced at the type level
Dynamic prompting _build_system_prompt(available_data) Prompt grounded in live DB contents — no hardcoded service names
Tool sandboxing Blocklist + threading timeout Allows math/stats scripts; blocks filesystem, network, and subprocess access
DB as IPC SQLite WAL, single dashboard_state row Agent and TUI share state atomically without message passing
Usage limits UsageLimits(request_limit=25) Hard cap prevents infinite tool loops and runaway costs
Audit logging Per-session JSONL via logging.py Full message history, tool calls, and rejections recorded for analysis
Freezeable UI DashboardState.frozen = true Agent can pause dashboard refresh during synchronous inspection windows

🖥️ TUI App

Panel Architecture

Abstract Panel base class with template methods: make_widget(), poll(state), on_mount(). Each panel owns its widget and self-refreshes on 0.5s interval from DB state.

Overview TimeSeries Histogram Logs

State Model

DashboardState Pydantic model holds all view config: active panels, metric/service filters, time range, log filters, agent status, and frozen flag. Persisted as single DB row.
